Classroom guide

A short, flexible sequence for exploring searching and sorting algorithms through prediction, tracing, and pseudocode development.

Suggested 50–60 minute lesson

  1. 5 min: Compare the four algorithms and their input requirements.
  2. 15 min: Explore each animation with Play, Next, and Previous. Ask students to predict the next index.
  3. 15 min: Complete the three Trace Lab tasks for one searching and one sorting algorithm.
  4. 15–20 min: Write pseudocode using a starter, then run all automated tests and inspect errors.
  5. Exit ticket: Explain when binary search is a good choice and how bubble differs from selection sort.

Important algorithm concepts

  • Linear: May operate on unsorted data; checks one element at a time.
  • Binary: Requires sorted data; repeatedly discards half the remaining range.
  • Bubble: Compares adjacent items, swapping those out of order. The largest remaining value settles at the end after each pass.
  • Selection: Finds the smallest remaining value and places it at the current position.
  • All visuals and code use 0-based indices and ascending sorting.

Running and sharing

This is one standalone .html file. Open it in Chrome, Edge, Safari, or Firefox, even without an internet connection. Upload the file to GitHub Pages or another static host to share a link with students.

The program needs no external libraries or internet services, and does not collect student names or results on a server.

Saved work and limitations

Trace responses and pseudocode are saved using the local browser storage on the same device. Work will not sync between devices; clearing browser data can erase it. Encourage students to copy their work if switching devices.

The pseudocode tester supports a clearly defined educational subset, not every possible IB pseudocode expression. It limits execution steps to stop infinite loops. Tested performance values refer to these implementations: unoptimized bubble sort always performs its fixed passes.
